# 扩展开发指引

新增内容或动作时，按下面的清单对照修改，避免漏改导致编译不过或两端不同步。
本文档专注于描述数据流与数据同步问题，为后续功能拓展理清结构

## 关键结构
### 数据上行流程 客机-主机
    - InputPacket     网络传输包结构体，定义所有输入操作，实现了INetworkSerializable
        - NetworkSerialize    定义网络序列化，由BufferSerializer负责解包打包，传入本地参数引用
        
    - InputManage                 输入管理系统，负责输入检测，网络包打包并发送，主机端解包事件
        - Input_get               每帧获取输入
        - SendPacket              固定时段发送状态包，传递 InputPacket 
        - GetPacket               本地打包方法，组装 InputPacket
        - SubmitInputServerRpc    主机传递网络包方法，主机端接收包并调用本地Input_event事件
        - Input_event             主机端解包事件    
        - 若干本地玩家值计算方法作为传送值
    
    -  HostNetWorkInputEvent       PlayerControl的主机网络包解包组件，取结构体内值转为主机各玩家状态
        - Input_Resolve           数据注入方法，注册到Input_event，识别本机对象接收本机InputPacket
        - Update                  组件自驱动事件分发，永久更新InputPacket到Player_Control下其注册方法，传递结构体到Player_Control下的中转变量下，完成控制器本地变量注入                               
        - 若干各状态其对应事件，由Player_Control负责事件注册，负责变量注入

    - Player_Control              玩家对象在各机上的总控制与表现器，玩家最终描述组件

### 数据下行流程 主机-客机

    - Player_Control              玩家对象在各机上的总控制与表现器，玩家最终描述组件
    其同步数据清单
```csharp
    NetworkVariable<ushort> netShowState = new NetworkVariable<ushort>();    //表现状态位
    NetworkVariable<Vector3> netAimPoint = new NetworkVariable<Vector3>();  //瞄准落点
    NetworkVariable<Vector3> netTargetPos = new NetworkVariable<Vector3>(); //锁定点
    NetworkVariable<bool> netHasTarget = new NetworkVariable<bool>();       //是否锁定
    NetworkVariable<float> netAimAngle = new NetworkVariable<float>();     //精度圈角度
    NetworkVariable<int> netHealth = new NetworkVariable<int>();            //玩家血量
    NetworkVariable<int> netAmmo = new NetworkVariable<int>();              //剩余弹药
    NetworkVariable<int> netRespawnIndex = new NetworkVariable<int>();      //复活点编号
    NetworkVariable<int> netScore = new NetworkVariable<int>();             //玩家积分
    NetworkVariable<float> netRespawnWait = new NetworkVariable<float>();   //等待剩余
    NetworkVariable<bool> netOut = new NetworkVariable<bool>();             //已淘汰
    NetworkVariable<float> netStamina = new NetworkVariable<float>(100f);   //当前体力
```
    统一规则：主机写入，客机读取。初始化值在 Player_Control_Start 补写，其中 netRespawnIndex 是必须的
    （它只在楼层上移时才写，不补初值客机会一直读到 0）；netHealth / netAmmo / netStamina 每帧都写，补初值只是让客机第一帧就有值。

        - netShowState    Player_Control_Date_HostUpdate 下由 PackShowState 打包下发
                          客机 Player_Control_Show_ClientUpdate 解包，驱动动画与音效
        - netAimPoint     Player_Control_Date_HostUpdate 下由 packet.aimPoint 传递，仅举枪时写
                          客机 Player_Control_Show_ClientUpdate 非本机举枪时取作瞄准点
        - netTargetPos    Player_Control_Date_HostUpdate 下由 Con_gun_Control.TargetPos 传递，仅举枪时写
                          客机 SetAimShow 显示锁定点
        - netHasTarget    Player_Control_Date_HostUpdate 下由 isAimDown && Con_gun_Control.HasTarget 传递
                          客机 SetAimShow 决定是否显示锁圈
        - netAimAngle     Player_Control_Date_HostUpdate 下由 Con_gun_Control.CurrentAngle 传递
                          客机 SetAimShow 驱动精度圈收缩
        - netHealth       Player_Control_Start 初始化写入
                          Player_Control_Date_HostUpdate 下由 Con_ObjectSystem.HP 传递
                          客机 Player_Control_Show_ClientUpdate 回写本地 Con_ObjectSystem.HP
        - netAmmo         Player_Control_Start 初始化写入
                          Player_Control_Date_HostUpdate 下由 Con_gun_Control.ammo 传递
                          客机 Player_Control_Show_ClientUpdate 回写本地 Con_gun_Control.ammo
        - netRespawnIndex Player_Control_Start 初始化写入
                          Player_Control_Date_HostUpdate 下按楼层上移推进
                          RespawnIndex 属性读取，复活取点用
        - netScore        Score_Add 累加写入，仅主机，击杀与伤害分来源
                          Score 属性读取，积分榜与右上角显示用
        - netRespawnWait  Player_Death_Date 写入初值，Player_Control_Date_HostUpdate 每帧倒数递减
                          复活时写 0
                          RespawnWait 属性读取，死亡幕布显示倒计时
        - netOut          Player_Out_Date 写入 true，仅主机，写后不回退
                          Is_Out 属性与多处逻辑守卫读取，判定淘汰与胜负
        - netStamina      Player_Control_Start 初始化写入
                          Player_Control_Date_HostUpdate 下由 Con_move.stamina 传递
                          客机 Player_Control_Show_ClientUpdate_Own 校正本机预测

        - 每帧写：netShowState、netHealth、netAmmo、netStamina、netHasTarget、netAimAngle、netRespawnWait
          注意 HostUpdate 有提前 return：非法、死亡等待复活、已淘汰时都会跳过
        - 条件下写：netAimPoint、netTargetPos（仅举枪时）、netRespawnIndex（仅楼层上移时，且只增不减）
        - 事件驱动写：netScore（Score_Add 累加）、netOut（Player_Out_Date 一次性）
          netRespawnWait（死亡与复活时写初值）


## 关键概念
### NGO 的 RPC 参数有类型限制
[ServerRpc] 方法的参数不是随便什么类型都能用的。NGO 在编译期（ILPP）会扫描你的 RPC 方法，要求每个参数必须是它能序列化的类型，比如：

内置类型：int、bool、float、Vector3、string、数组等；
实现了 INetworkSerializable 的自定义类型；
实现了 INetworkSerializeByMemcpy 的非托管类型；
FixedString、NativeArray 等特殊类型。
如果你传一个没实现这些接口的普通 struct，编译期或运行时会直接报错，NGO 根本不会让你通过。

所以不是“必须用 INetworkSerializable 的引用”，而是必须用 NGO 认识的可序列化类型。INetworkSerializable 只是其中一种，也是最常用的一种。

### NetworkVariable<T> 的泛型参数 T 被限制为 非托管（unmanaged）类型。这意味着：

类型必须是结构体：不能是 class。因为 class 可以为 null，而 NetworkVariable 不支持可空类型。

所有字段（包括嵌套字段）都不能是引用类型：这排除了 string、数组、class 等。一个包含 string 字段的结构体，即使实现了 INetworkSerializable，也无法用于 NetworkVariable。

因此，你的 InputPacket 结构体可以用于 NetworkVariable，因为它只包含了 ulong、Vector3、Vector2、bool 这些非托管类型，完全符合要求。

## 一、数据流总览

```mermaid
graph TD
    A[Input_Manage<br/>读键] --> B[InputPacket<br/>网络输入包]
    A --> D[Local_InputEvent<br/>本机预测事件]
    B --> C[HostNetWorkInputEvent<br/>主机事件]
    C --> E[Player_Control<br/>主机权威逻辑]
    D --> F[Player_Control<br/>客机预测]
    E --> G[Player_Body / Gun_Control / Object_System]
    E --> H[netShowState 等网络变量]
    H --> I[Player_Control_Show_ClientUpdate<br/>各端表现]
    F --> J[Player_Control_Show_ClientUpdate_Own<br/>本机表现]
    I --> K[Player_animation / Player_Audio]
    J --> L[Player_camera / Hit_Feedback_UI]

    本机Input读取 InputPacket
```

驱动顺序由 `Player_Main` 统一控制：`Player_Control_Date_HostUpdate` → `Player_Control_Show_ClientUpdate` → `Player_Control_Show_ClientUpdate_Own`，物理帧为 `Player_Control_Date_HostFixedUpdate` / `Player_Control_Date_ClientFixedUpdate_Own`。

## 二、新增一个按键输入

五个文件，顺序不能漏。

1. `core/Input_Manage.cs`
   - 声明 `public bool XXHeld;`
   - 按键读取处加 `XXHeld = Input.GetKey(KeyCode.XX);`
   - 打包处加 `packet.xx = XXHeld;`
2. `core/InputPacket.cs`
   - 加 `public bool xx;`，并在 `NetworkSerialize` 里加一行序列化
3. `Player/HostNetWorkInputEvent.cs`
   - 加 `public event Action<bool> XX_event;`
   - `Update()` 里加 `XX_event?.Invoke(packet.xx);`
4. `Player/Local_InputEvent.cs`
   - 同名事件 + `Update()` 里从 `input_Manage.XXHeld` 分发
   - 顺序要与 `HostNetWorkInputEvent` 保持一致
5. `Player/Player_Control.cs`
   - 加中转字段 `public bool isXXDown;`
   - `RegisterInputEvents` / `UnregisterInputEvents` 注册反注册
   - `RegisterPredictEvents` / `UnregisterPredictEvents` 注册反注册
   - 加处理方法 `void OnXX(bool on)`

> `Local_InputEvent` 只在客机本机运行（`RegisterPredictEvents` 里有 `if (IsServer || !IsLocalPlayer) return;`），主机本人走 `HostNetWorkInputEvent`。

## 三、新增一个状态位（同步表现）

1. `Player/Player_animation.cs`
   - 加 `public const ushort BitXX = 1 << N;`
   - `Player_animation_Show` 里加 `animation.SetBool("XX", (state & BitXX) != 0);`
2. `Player/Player_Control.cs`
   - `PackShowState()`（主机）和 `PackLocalShowState()`（客机本机）都要置位
3. Unity Animator 里加同名参数

位分配现状（`ushort` 共 16 位）：

- 0-7：Walk / Run / Squat / Gun / Jump / Ground / Death / Roll
- 8-9：MoveX（2 位有符号）
- 10-11：MoveY（2 位有符号）
- 12：WeightLess
- 13-15：**空闲，新位优先用这里**

## 四、新增一个玩家动作（物理类，如跳跃/翻滚）

以跳跃为模板，主机和客机各走一遍。

1. `Player/Player_Control.cs`
   - 输入处理方法里记边沿：`if (on && !isXXDown) xxRequest = true;`
   - 主机 `Player_Control_Date_HostFixedUpdate`：`if (xxRequest) { xxRequest = false; Con_body.Body_XX_Date(); }`
   - 客机 `Player_Control_Date_ClientFixedUpdate_Own`：同样处理（预测）
2. `Player/Player_Body.cs`
   - 加动作本体，物理一律用 `rb.AddForce`
   - 若动作要突破 `Body_Fixed_Date` 的水平限速，需要在限速前放行
3. `Player/Player_animation.cs` 加状态位（可选）
4. `Assets/Player_Audio.cs` 加音效（可选）

> 关键：动作的**触发边沿**只能在输入事件里产生，两边各自消费一次，不要在网络事件里做状态判断。

## 五、新增一个玩家音效

1. `Assets/Player_Audio.cs`
   - `AudioNumKV` 枚举**只能往末尾追加**，插中间会让 Inspector 里已绑的片段整体错位
   - 选音源：一次性反馈用已有的 `hitSource` / `shotSource`；持续循环必须新开 `AudioSource` 字段
   - 加公开方法 `XX_Show()`
2. 触发方调用：本机表现放 `Player_Control_Show_ClientUpdate_Own`，各端表现放 `Player_Control_Show_ClientUpdate`
3. Inspector：扩 `audioClips` 数组、绑新音源

**音源使用铁律**

- `Play()` / `Stop()` 作用于**整个音源**，会连带掐掉该源上所有 `PlayOneShot` 的声音
- 要"不硬切、播完当前一轮"，用 `loop = false`，不要用 `Stop()`
- 循环音用 `if (!isPlaying) Play();` 防每帧重启
- 2D 反馈音设 `Spatial Blend = 0`；一旦为 0，`Min/Max Distance` 和衰减全部失效

1. `Player/Player_Control.cs` 加 `NetworkVariable<T> netXX = new NetworkVariable<T>();`

## 八、新增一个关卡时间节点

**先想清楚是否真的需要节点。**

`nodeTime`、`nodeGasY`、`gasNode`、`switch (index)` 四处都按顺序硬编码，`nodeTime` 插一项就会让后面所有下标错位。纯表现型的时间点（音乐、提示音）不要加节点，改成在 `Player_level_FixUpdate_Performance(time)` 里判时间。

确需加节点时：

1. `Level/Player_level.cs`
   - `nodeTime` 插入（保持升序）
   - `nodeGasY` **同步插入**占位（非毒气节点填 0）
   - 加 `TimeXX_event`
   - `Player_level_Event_Date` 的 `switch` 加 case
   - 若有毒气节点，`gasNode` 数组同步更新
2. `UI/UI_Time.cs`：`eventTime` / `eventName` / `tipAhead` 同步
3. `Player_Main.cs` 不用改，`Node_event` 是通用分发

## 九、新增一个关卡音效（警报/音乐/提示）

1. `Level/Player_level.cs`
   - 加 `AudioSource` + `AudioClip` + 提前秒数 + `bool` 标志
   - `Player_Level_Init` 里重置标志并 `Stop()`
2. 触发点二选一
   - 按时间：`Player_level_FixUpdate_Performance(time)`，各端都会跑
   - 按节点：`Player_level_Event_Date(index)`，各端由节点广播驱动
3. Inspector 绑音源

> `Player_level_FixUpdate_Performance` 里**绝对不能用 `return` 提前退出**，否则排在后面的逻辑全被挡掉。改 `if (...) { ... }` 条件块。

## 十、新增一个场景交互物体

1. 脚本实现 `IScene_Interaction` 接口，写 `Scene_Interaction(Player_Control control)`
2. 挂在带 `Collider` 的物体上
3. 玩家侧自动检测，不用手动注册（`Player_Scene_Interaction_Date` 用 OverlapBox）
4. 该接口是**持续调用**，不是进出回调

**判定陷阱**：检测范围内有物体不等于有玩家。不要用 `hits.Length > 0` 当门槛，要先循环找出真正的 `Player_Control`：

```csharp
bool isplayer = false;
for (int i = 0; i < hits.Length; i++)
{
    if (hits[i].GetComponent<Player_Control>()) { isplayer = true; break; }
}

if (isplayer && in_player != null) { /* 有人在 */ }
else { /* 人已离开，清状态 */ }
```

用 `hits.Length` 当门槛会导致玩家离开后仍走"有人"分支，状态永远不清空，事件不再触发。

## 十三、铁律

- 空引用一律 `Debug.LogError("脚本名|方法|原因")`，可选的展示类依赖除外
- 注释写在字段行尾或方法上一行，不超过 15 字
- 方法收数据作参数，内部不自己取数据
- 主机权威算逻辑，客机只做预测与表现
- 派生状态优于事件通知，单一真源
- 枚举、数组只往末尾追加，不插中间
- 表现层不要写 `Update`，由 `Player_Main` 逐层驱动

## 十四、踩过的坑

- **调用点没跟上改签名**：`Takedamage` 加 `out bool killed`、`Hit_Feedback_UI_Show` 加 `score` 参数，改完接口要全局搜一遍调用点
- **射速单位**：`fireRate` 是发/分钟，间隔必须用 `60f / fireRate`；主机和客机写了两套公式就会出现某一端射速翻几倍
- **`WaitForSeconds` 累计误差**：逐次等待每次至少多一帧，一段十几行能拖出好几秒。要按绝对时间锚定：`float target = startTime + n * interval; while (Time.time < target) yield return null;`
- **`AudioSource.Play/Stop` 是源级的**：会掐掉同源上所有 `PlayOneShot`
- **`Spatial Blend = 0` 会让所有距离参数失效**，调范围没反应先查这里
- **枚举中间插项**：Inspector 已绑定的片段整体错位
- **`nodeTime` 插项**：后续下标全部错位
- **`hits.Length > 0` 当有人判定**：掩盖"玩家已离开"
- **状态位是 `ushort`**：位用完要及时改 `uint` 并同步 `NetworkVariable` 类型
- **登录场景交叉验证**：NGO 对场景里的 `NetworkObject` 会强制 `DestroyWithScene = true`，常驻单例不能放在场景对象上
- **`SpawnAsPlayerObject` 默认 `destroyWithScene = false`**：玩家对象换场景不会自动销毁，要手动 `Despawn(true)`
