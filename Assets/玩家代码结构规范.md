# 玩家代码结构规范（供网络模块接入）

> 适用：`Assets/Script` 下玩家相关脚本
>
> 范围：只描述本地代码怎么拆、要暴露哪些接入点。网络模块（NetworkBehaviour / ServerRpc / ClientRpc / NetworkVariable）由另一位负责，本文不含其写法。
>
> 最后整理：2026-09-21

---

## 0. 一句话结构

输入层只发事件；`Player_Control` 是唯一的粘合层，也是唯一的接入点；组件层（Body / Gun / anim）只管本地表现，不认识网络。动作是方法，不做数据层。

### 已确认的架构决策（2026-09-22）

| # | 决策 | 对本地代码的影响 |
|---|---|---|
| 1 | 开火走主机权威：`ApplyFire` 由主机裁决后广播，参数必须带**开火点**与**方向向量** | `RequestFire` 必须把客户端本地算出的开火点与方向一起交出去，不能只发一个"我要开火" |
| 2 | 移动走客户端权威：客户端自己算移动与位置，网络只负责传输角色信息（沿用 `NetworkTransform`） | 主机不重算移动，`Player_Body` 里不出现任何网络判断；非本地玩家的刚体保持运动学，只被 `NetworkTransform` 驱动 |

这两条是咬合的：因为移动由客户端权威，主机上那个玩家的位置是插值出来的，主机自己算不出准确的枪口位置，所以开火点必须由客户端在开火那一刻采集并上行。这不是多此一举，而是客户端权威移动的必然结果。

选客户端权威移动的主要理由：移动逻辑只保留一套。移动与位置计算全部写在本地玩家的 `Player_Body` 里，主机不重算、客户端也不必另外写一份，网络只负责把角色信息传出去。

## 1. 本文的边界

| 本规范负责 | 不属于本规范 |
|---|---|
| `Assets/Script` 下玩家脚本的拆分、命名、职责 | `NetworkBehaviour` / `ServerRpc` / `ClientRpc` / `NetworkVariable` 的写法 |
| 输入 → 请求 → 表现 这条调用链 | Relay、连接、房间、场景切换 |
| 组件层（Body / Gun / anim）的方法化改造 | 玩家与敌人的生成、销毁策略（Spawn / Despawn） |
| 把接入点（请求出口、表现入口）暴露清楚 | 预制体上 `NetworkObject` / `NetworkTransform` 的参数 |
| 保证不连网时本地也能跑起来 | 反作弊、延迟补偿、回放 |

一句话：本文负责"把代码改成一插就通的样子"，插的那根线由网络模块负责。

## 2. 目标目录结构

```
Assets/Script/
├─ Core/
│   ├─ Idamage.cs            受击接口（保留；以后可改名 IDamageable，纯改名不急）
│   ├─ Character_Move.cs     共用基类：SmoothRotate / AimGun / 速度字段（玩家与敌人共用）
│   ├─ GameManager.cs        只负责：游戏状态机 + 唯一一处生成玩家 + 绑定本地相机
│   └─ Start_Main.cs         只负责：连接 UI，删掉自己的 SpawnPlayer
├─ Player/
│   ├─ Player_Input.cs       输入层：唯一读 Input 的地方，只发事件
│   ├─ Player_Control.cs     粘合层 + 唯一接入点
│   ├─ Player_Body.cs        人物控制组件：移动 / 跳跃 / 蹲 / 跑 / 转向 / 瞄准
│   ├─ Player_Gun.cs         枪械组件：射线、弹药、后坐力、枪口火焰（原 Gun_Control）
│   └─ Player_anim.cs        动画组件：只提供 SetXxx 方法（原 Player_animation）
├─ Camera/
│   └─ Player_camera.cs      相机组件（视角自己读鼠标，见 6.6）
└─ Enemy/                    先空着，等受击方案定了再放
```

命名与改动规则：

- 文件里的 `public` 类名必须与文件名一致。
- 改名一律用 Unity 里右键 Rename，`.meta` 一起走、GUID 不变，预制体引用不会丢。
- 组件层（`Player_Body` / `Player_Gun` / `Player_anim`）不允许出现 `using Unity.Netcode`、`NetworkObject`、`IsOwner`。整个工程里这些只允许出现在 `Player_Control`（以及网络模块自己的文件里）。

## 3. 预制体挂载与引用关系

`Player.prefab` 现有结构保持不变，只调整脚本职责：

```
Player                       (NetworkObject, NetworkTransform, Rigidbody, CapsuleCollider, Object_System)
├─ Player_Input
├─ Player_Control
├─ Player_Body
├─ Player_anim
└─ 人物
   └─ 枪械1                 (LineRenderer, AudioSource, ShootPoint)
      └─ Player_Gun
```

两条硬规则：

- 预制体上的 `NetworkObject` / `NetworkTransform` 由网络模块负责，不要删、不要改参数，本地代码也不要依赖它们。
- 引用方向固定为单向：`Player_Control` 引用 `Player_Input` / `Player_Body` / `Player_Gun` / `Player_anim` / 本地相机，反向不引用。组件之间不互相持有引用，需要联动时由 `Player_Control` 转发。

**事件注册统一用代码 `AddListener`，不要在 Inspector 里连 UnityEvent。** 预制体上的序列化引用一旦丢就是 `{fileID: 0}`。现在 `Player_Control` 的 `Player_camera`、`uiFocuspos`、`camShake` 已经是空的，靠 `SetupLocal` 运行时注入才活下来。

## 4. 核心：把每个动作拆成"请求"和"表现"两类方法

开火、瞄准、换弹、跳跃、蹲、跑、移动，每个动作在 `Player_Control` 里都对应两个方法：

| 类别 | 方法名示例 | 谁调用 | 要求 |
|---|---|---|---|
| 请求 Request | `RequestFire` / `RequestAim(bool)` / `RequestReload` / `RequestJump` / `RequestMove(Vector2)` / `RequestSquat(bool)` / `RequestRun(bool)` | `Player_Input`（本地输入） | 表示"我想做这个动作"。默认实现直接走本地表现，能单机跑；接入网络后由网络模块接管，改成发请求给主机。**需要数据的动作（开火）必须把数据一起带上** |
| 表现 Apply | `ApplyFire(Vector3 origin, Vector3 direction)` / `ApplyAim(bool)` / `ApplyReload` / `ApplyJump` / `ApplyMove(Vector2)` / `ApplySquat(bool)` / `ApplyRun(bool)` | `Player_Control` 内部（默认实现）、网络模块（收到权威结果后） | 幂等、无结算、任何端都可调用。**开火是主机权威，必须带开火点与方向** |

四条规定：

- `Apply` 里绝对不能出现：扣弹药、扣血、修改权威状态、判断"能不能做"。这些只出现在请求的裁决里。
- `Apply` 必须可重复调用且结果一致（同样的参数调一次和调三次效果相同）。网络模块可能让它在本地和远端各触发一次。
- 请求里的本地校验（例如 `if (!gun.CanFire()) return;`）在接入后要交给裁决方（开火是主机）。所以校验必须写成独立的查询方法（`CanFire()`），不能写死在 `Request` 里，否则接入时只能删代码。
- 需要数据的动作，数据必须在**按下那一刻**采集一次并随请求上行，不能等广播回来再算（那时位置和朝向已经变了）。

骨架（不含任何网络代码，现在就能跑）：

```csharp
// Player_Control：以"开火"这一个动作为例
public void RequestFire()                 // 本地输入触发（按住连发时每帧调，由 CanFire 限流）
{
    Vector3 origin = gun.MuzzlePosition;      // 开火点：本机枪口世界坐标
    Vector3 dir    = body.GetAimDirection();  // 方向：本机相机 + 准星算出的单位向量

    if (!gun.CanFire()) return;               // 单机模式的本地校验；接入后挪到主机
    ApplyFire(origin, dir);                   // 单机时直接表现
    // 接入后：把 (origin, dir) 交给网络模块上行，这里不再直接 Apply
}

public void ApplyFire(Vector3 origin, Vector3 direction)   // 表现入口：主机权威，各端复现
{
    gun.FireVisual(origin, direction);    // 枪口火焰 / 射线 / 音效 / 后坐力
    cam.Shake();                          // 只有本地玩家的 cam 非空，天然只对本机生效
}
```

两个数据的来源都是只读查询，不改状态：

| 数据 | 由谁提供 | 怎么算 |
|---|---|---|
| 开火点 `origin` | `Player_Gun.MuzzlePosition` | 枪口（`shootPoint`）的世界坐标 |
| 方向 `direction` | `Player_Body.GetAimDirection()` | 相机经准星 UI 发出的射线方向，归一化；没有相机时退回人物朝向 |

接入网络时只需要动这两处，`Player_Gun` / `Player_Body` / `Player_anim` 一行都不用改：

1. `RequestFire` 里"本地校验 + 直接 Apply"换成"把 `(origin, direction)` 交给网络模块"（怎么写由网络模块负责）。
2. 网络模块收到主机的权威结果后调用 `ApplyFire(origin, direction)`。

一个提醒：由于 `ApplyFire` 是主机权威，`RequestFire` 里那次本地 `Apply` 在接入时要去掉，否则发起者会看到两次（一次本地、一次广播回来）。表现统一由主机的结果驱动，而不是各端自己算。

还没定的一条：主机判定完之后，要不要把命中点 / 是否命中一起下发（这样各端连射线都不用自己算，表现也最一致）。这条留到第 12 节，等网络模块答复。

## 5. 数据流（本地视角）

```
开火（主机权威）
本地输入按下
   │
   ▼
Player_Input.FireHeld ──► Player_Control.RequestFire()
                             │  采集：origin    = gun.MuzzlePosition
                             │        direction = body.GetAimDirection()
                             ▼
                     现在（不连网）：直接 ApplyFire(origin, direction)，本地表现
                     接入后：把 (origin, direction) 上行 → 主机裁决（射线 / 伤害）
                                   │
                                   ▼
                     广播回各端（含主机），每个端各调用一次
                                   │
                                   ▼
                     Player_Control.ApplyFire(origin, direction)
                                   │
                                   ▼
                     Player_Gun.FireVisual + Player_camera.Shake

移动（客户端权威）
本地输入 ──► RequestMove ──► Player_Body 在本机算物理与位置
                                   │
                                   ▼
                     网络只负责传输角色信息（NetworkTransform 同步）
                     主机不重算移动；非本地玩家的刚体保持运动学，只被同步驱动

其他动作（瞄准 / 换弹 / 跳跃 / 蹲 / 跑）
本地输入 ──► Player_Control.RequestXxx
                ├─ 现在：直接 ApplyXxx
                └─ 接入后：由网络模块处理，结果回来调 ApplyXxx
```

## 6. 接口契约

### 6.1 Player_Input（输入层）

只做两件事：读输入、发事件。不做本地玩家判断，不做能不能开火的判断，不引用任何组件。

```csharp
public class Player_Input : MonoBehaviour
{
    public UnityEvent FireDown;          // 左键按下的那一刻，触发一次
    public UnityEvent FireHeld;          // 左键按住期间，每帧触发（连发用）
    public UnityEvent FireUp;            // 左键抬起
    public UnityEvent AimDown;           // 右键按下
    public UnityEvent AimUp;
    public UnityEvent Reload;            // R
    public UnityEvent Jump;              // 空格
    public UnityEvent<bool> Squat;       // 状态变化时触发一次
    public UnityEvent<bool> Run;         // 状态变化时触发一次
    public UnityEvent<Vector2> Move;     // 每帧：本地输入向量

    // 动作入口：本地输入的唯一落点
    public void Event_Fire();
    public void Event_FireHeld();
    public void Event_Aim(bool on);
    public void Event_Reload();
    public void Event_Jump();
    public void Event_Squat(bool on);
    public void Event_Run(bool on);
    public void Event_Move(Vector2 input);
}
```

两个必须交代的点：

**一、按住连发要保留。** 现在是按住左键持续开火、由 `Gun_Control` 内部的射速判定限流。所以开火事件不能只有"按下那一刻"，必须同时提供"按住期间每帧"。`Player_Control` 把 `FireHeld` 注册到 `RequestFire`，由 `CanFire()` 限流（所以上行频率约等于射速，不会每帧都发）；`FireDown` 留给以后需要"按下瞬间"的逻辑，例如单发武器、开镜。

**二、开火点与方向不经过事件。** 这两个值由 `Player_Control.RequestFire()` 在按下那一刻向 `Player_Gun` 与 `Player_Body` 取，让 `Player_Input` 保持不引用任何组件：

| 方案 | 开火事件签名 | 谁采集数据 | 评价 |
|---|---|---|---|
| A（推荐） | `UnityEvent FireDown` / `FireHeld`，无参 | `Player_Control` 在回调里取 | 输入层保持纯净，方向永远是开火那一刻的值 |
| B | `UnityEvent<Vector3, Vector3> FireDown`（开火点, 方向） | `Player_Input` 自己算，需要引用 `Player_Gun` 与相机 | 网络模块能直接从事件取值，但输入层被污染，且事件每帧触发时方向与开火瞬间容易不同步 |

如果网络模块坚持直接从事件上取值，用方案 B 也能跑，只是要在 6.7 的清单里注明 `Player_Input` 从"不引用组件"变成了"需要引用 `Player_Gun` 与相机"。

`Event_Xxx` 系列保留原来的命名习惯，它就是 `Player_Control.RequestXxx` 的触发源，别在这里放任何逻辑。

### 6.2 Player_Control（粘合层，唯一接入点）

职责：持有组件引用、注册事件、把输入转成请求、把请求转成表现、绑定本地相机与 UI。

注册关系（全部代码 `AddListener`，`Player_Control` 是唯一注册者）：

| 输入事件 | 注册到的方法 |
|---|---|
| FireHeld | `RequestFire`（连发；由 `CanFire()` 限流，上行频率约等于射速） |
| FireDown | 暂时不注册，留给单发武器 / 开镜等"按下瞬间"的逻辑 |
| AimDown / AimUp | `RequestAim(true)` / `RequestAim(false)` |
| Reload | `RequestReload` |
| Jump | `RequestJump` |
| Squat(bool) | `RequestSquat` |
| Run(bool) | `RequestRun` |
| Move(Vector2) | `RequestMove` |

请求与表现的内部对应（现在的默认实现，接入后第二列由网络模块驱动）：

| 请求（本地输入） | 表现（人人可调，幂等） | 内部调用 |
|---|---|---|
| `RequestFire` | `ApplyFire(Vector3 origin, Vector3 direction)` | `gun.FireVisual(origin, direction)` + `cam.Shake` |
| `RequestAim(bool)` | `ApplyAim(bool on)` | `body.SetAim` + `anim.SetRaiseGun` + `cam.SetShoulderAim` |
| `RequestReload` | `ApplyReload()` | `gun.Reload` |
| `RequestJump` | `ApplyJump()` | `body.Jump` + `anim.SetJump` |
| `RequestSquat(bool)` | `ApplySquat(bool on)` | `body.SetSquat` + `anim.SetSquat` |
| `RequestRun(bool)` | `ApplyRun(bool on)` | `body.SetRun` + `anim.SetRun` |
| `RequestMove(Vector2)` | `ApplyMove(Vector2 input)` | `body.SetMoveInput` |

另外保留 `SetupLocal(cam, camRig, ui)`：给本地玩家绑定相机与准星 UI，同时把相机与准星注入 `Player_Body`（`GetAimDirection` 要用）。是否启用 `Player_Body` 的输入与瞄准，由 `Player_Control` 决定（接入后由网络模块告诉它"这是我的角色"）。

非本地玩家的 `camShake` 为空，`ApplyFire` 里的震屏自然空转，这就是"只对本机表现"的天然过滤器。

### 6.3 Player_Body（人物控制组件）

继承 `Character_Move`，复用 `SmoothRotate` / `AimGun` / 速度字段。

```csharp
public class Player_Body : Character_Move
{
    public void SetupContext(Camera cam, RectTransform uiFocus);   // 本地玩家才注入
    public void SetMoveInput(Vector2 input);   // 每帧：缓存输入，FixedUpdate 施加力
    public void SetRun(bool on);
    public void SetSquat(bool on);
    public void SetAim(bool on);               // 举枪姿态
    public void Jump();
    public Vector3 GetAimDirection();          // 只读：相机经准星的方向，归一化
    public Vector3 GetAimPoint();              // 只读：瞄准点（命中点或固定焦点）
    public bool IsGrounded { get; }            // 供 anim 与外部查询
    public bool IsMoving { get; }
}
```

外部只通过方法改变状态，不再让别人直接读 `isMouse1Down` 这类字段。

移动是客户端权威，所以本组件里有两条规矩：

- 只有本地玩家的实例跑输入与物理（施力、限速、转向）；非本地玩家的刚体保持运动学，位置完全由网络同步驱动，本组件不做任何网络判断。
- 移动与位置计算只有这一套实现：谁的实例是本地玩家，谁就跑这套，主机和客户端不分写两份逻辑。
- 现在 `Player_Control.FixedUpdate` 里那段瞄准射线（`TryGetAimPoint`，忽略 `Player` 标签）搬到本组件，随 `GetAimPoint()` / `GetAimDirection()` 一起供外部查询。

### 6.4 Player_Gun（枪械组件）

```csharp
public class Player_Gun : MonoBehaviour
{
    public Vector3 MuzzlePosition { get; }     // 只读：枪口（shootPoint）世界坐标
    public bool CanFire();                     // 弹药 + 射速校验（查询，不改状态）
    public bool CanReload();                   // 查询
    public void ConsumeAmmo();                 // 结算，只由裁决方调用
    public void FireVisual(Vector3 origin, Vector3 direction);   // 只做表现：射线、枪口火焰、音效、后坐力
    public void Reload();
    public void SetRecoilReduction(bool on);
}
```

注意事项：

- 伤害结算（`GetComponent<Idamage>().Takedamage`）移出本文件，交给裁决路径处理（见第 12 节待对齐项）。
- 参数只用基础类型与 `Vector3`，不要用 `Transform` / `GameObject` 当参数（网络那边传不过来）。
- 不要用返回值承载"这次动作成功了吗"，改成独立查询方法（`CanFire()`）。
- `FireVisual` 不再自己算方向，方向由参数进来；各端复现同一条射线，表现才一致。
- 随机后坐力偏移挪到"采集方向"这一步（客户端按下那一刻应用，随请求上行），不要留在 `FireVisual` 里各自随机，否则各端看到的射线方向不一样。

### 6.5 Player_anim（动画组件）

```csharp
public class Player_anim : MonoBehaviour
{
    public void SetRun(bool on);
    public void SetWalk(bool on);
    public void SetRaiseGun(bool on);
    public void SetSquat(bool on);
    public void SetJump(bool on);
    public void SetSuspended(bool on);   // 是否离地
}
```

替换掉现在每帧轮询 `player_Control.isXxx` 的 `FixedUpdate`。`Animator.SetBool` 本身幂等，重复调用无害，所以这些方法可以放心被反复触发。

### 6.6 Player_camera（相机组件）

唯一例外：视角自己读鼠标，本地权威，不过 `Player_Control`。把现在 `Update` 里那段 `Player != null ? Player.GetComponentInParent<NetworkObject>() : null` 的 `IsOwner` 判断删掉——是否绑定相机由 `Player_Control.SetupLocal` 决定。

瞄准方向由 `Player_Body.GetAimDirection()` 用主相机与准星算出，所以相机与准星要在 `SetupLocal` 时注入 `Player_Body`。本组件自己不查网络、不算瞄准，只做跟随、肩射偏移与震动。

### 6.7 接入点汇总（给网络模块看的清单）

| 接入点 | 位置 | 用途 |
|---|---|---|
| `RequestFire()` | `Player_Control` | 本地输入出口。接入后在这里把 `(origin, direction)` 上行给主机 |
| `RequestAim(bool)` / `RequestReload()` / `RequestJump()` / `RequestSquat(bool)` / `RequestRun(bool)` / `RequestMove(Vector2)` | `Player_Control` | 本地输入出口，网络模块在这一层接管 |
| `ApplyFire(Vector3 origin, Vector3 direction)` | `Player_Control` | **主机权威结果的下发入口**，各端各调一次 |
| `ApplyAim(bool)` / `ApplyReload()` / `ApplyJump()` / `ApplySquat(bool)` / `ApplyRun(bool)` / `ApplyMove(Vector2)` | `Player_Control` | 网络模块收到结果后回调这一层 |
| `MuzzlePosition` | `Player_Gun` | 只读，开火点的来源 |
| `GetAimDirection()` / `GetAimPoint()` | `Player_Body` | 只读，方向的来源 |
| `CanFire()` / `CanReload()` | `Player_Gun` | 查询，用于裁决 |
| `IsGrounded` / `IsMoving` | `Player_Body` | 查询 |
| `SetXxx` 系列 | `Player_Body` / `Player_anim` | 仅供 `Player_Control` 内部调用，网络模块不需要碰 |

移动不在这张表里：它是客户端权威，不经过"请求 / 回调"，网络只做传输（见 6.3）。

## 7. 命名与参数约定

| 前缀 | 含义 | 放在哪 | 谁调用 |
|---|---|---|---|
| `Event_Xxx` | 输入事件落点 | `Player_Input` | 输入检测代码 |
| `RequestXxx` | 动作请求 | `Player_Control` | `Player_Input` 的事件；接入后由网络模块接管 |
| `ApplyXxx` | 表现应用 | `Player_Control` | 本地默认实现；接入后由网络模块回调 |
| `CanXxx` | 状态查询（有返回值） | 组件层 | 任意 |
| `SetXxx` | 组件内部状态设置 | 组件层 | 仅 `Player_Control` |

参数与返回值规则：

- 参数只用基础类型：`bool` / `int` / `float` / `Vector2` / `Vector3` / `ulong`。
- 不要用 `Transform` / `GameObject` 当参数或返回值，网络那边传不过来。
- 不要用返回值表示"这次动作成功了吗"，改成独立的 `CanXxx()` 查询。
- 组件层不再暴露 `public` 状态字段（现在的 `isMouse1Down` / `isRuning` / `isSquat` 这些全部收进 `Player_Body` 或 `Player_Input`）。
- 要上行给主机的数据（开火点、方向等）必须由客户端在动作发生那一刻采集，不能靠主机重算。
- 表现方法要带齐复现所需的全部数据（开火 = 开火点 + 方向），别让各端自己重算，否则表现会不一致。

## 9. 建议落地顺序

1. 建 `Player_Input`，把 `Update` 里的输入检测抽出来。事件内部先直接调用原来的逻辑，行为保持不变，先跑通。
2. 抽 `Player_Body`：移动 / 跳跃 / 蹲 / 跑 / 瞄准。`Player_Control` 退化成粘合层，不再继承 `Character_Move`。
3. 抽 `Player_Gun`（原 `Gun_Control` 改名）与 `Player_anim`（改 `SetXxx`），顺手把 `CanXxx` 查询拆出来。
4. 在 `Player_Control` 里把每个动作补齐成 `RequestXxx` + `ApplyXxx` 一对（开火的 `ApplyFire` 带开火点与方向），并确认此时单机行为与改动前一致。
5. 收敛玩家生成：`Start_Main` 与 `GameManager` 只留一处。
6. 把 6.7 的接入点清单交给网络模块，按第 12 节的问题对齐后再接线。

第 1 至 4 步做完、且视觉与操作手感无变化，本地侧就算完成。这样出问题时能立刻判断是重构引入还是接线引入。

## 12. 需要和网络模块对齐的问题（交接清单）

### 已定（2026-09-22）

| 项 | 结论 | 对应的本地代码 |
|---|---|---|
| 开火权威 | 主机权威。客户端在开火那一刻采集开火点与方向上行，主机裁决后下发，各端复现 | `RequestFire()` 带上 `(origin, direction)`；`ApplyFire(origin, direction)` 由网络模块回调 |
| 移动权威 | 客户端权威。客户端算移动与位置，网络只传输角色信息，主机不重算，移动逻辑只有一套 | 沿用 `NetworkTransform`；`Player_Body` 的物理只由本地玩家的实例跑 |

### 待定

1. 主机判定后要不要把命中点 / 是否命中一起下发（决定 `ApplyFire` 要不要再加参数）。下发的好处：各端射线完全一致，客户端也不用自己 raycast。
2. 主机对客户端给的开火点 / 方向做不做合理性校验（客户端权威移动时，枪口位置理论上可以伪造）。
3. 客户端权威移动下，主机要不要做速度上限校验（防瞬移）。
4. 表现由网络广播统一触发（推荐，不会重复），还是本地先预测？决定 `RequestXxx` 里那次本地 `Apply` 要不要保留。
5. 抬枪 / 蹲 / 跑这些持续状态由谁写、谁读，本地要不要先预测。
6. 敌人受击：敌人是不是网络对象，伤害接口是否需要带"谁打的"参数。
7. 玩家生成与销毁：由哪一端生成，死亡后怎么处理（这块现在在 `GameManager` 与 `Start_Main` 里各有一份）。
8. 弹药与血量要不要同步给客户端（HUD 显示需要）。
9. 是否保留"不连网单机跑"的模式。
10. "这是我的角色"由哪一侧判断（现在 `Player_Control` 里有一行 `netObj.IsOwner`）。

## 13. 改动方式：哪些原地改、哪些新建

原则：**挂在预制体上的脚本一律原地改名 / 改写，只有"原来不存在的职责"才新建文件**，不要让新旧两个脚本并存。

| 文件 | 处理方式 | 说明 |
|---|---|---|
| `Player_Control.cs` | 原地改写 | 保留挂载点，先把输入抽走，再把移动 / 瞄准抽走 |
| `Player_Input.cs` | 新建 | 原来没有这个职责 |
| `Player_Body.cs` | 新建 | 从 `Player_Control` 切出来的移动 / 瞄准 |
| `Gun_Control.cs` → `Player_Gun.cs` | 原地改名 + 改写 | 用 Unity 里右键 Rename，`.meta` 一起走，枪上的组件引用不丢 |
| `Player_animation.cs` → `Player_anim.cs` | 原地改名 + 改写 | 同上 |
| `Character_Move.cs` | 原地改（只加不改签名） | 玩家与敌人共用，别动 `SmoothRotate` / `AimGun` |
| `Player_camera.cs` | 原地改 | 只删 `IsOwner` 那一段 |
| `Object_System.cs` | 原地改 | 删 `using UnityEditor;`，去掉自动 Destroy |
| `GameManager.cs` / `Start_Main.cs` | 原地改 | 收敛玩家生成入口 |
| `ClientNetworkTransform.cs` | 网络模块负责 | 见第 14 节 |

三条注意事项：

- 不要新建 `Player_ControlV2` / `Player_Control_New` 之类的替代脚本再删旧的：预制体上那一格会变成 `Missing (Mono Script)`，`Gun` / `gun_Control` / `Head` / `shootPoint` / `line` / `audioSource` 这些引用与数值都要重填。
- 新组件（`Player_Body`）是全新组件，`jumpForce` / `groundCheckDistance` / `focusDistance` / `Gun` / `Head` / `rb` 这些值不会自动带过去。动手前先把 `Player_Control` 的 Inspector 抄一遍，加完组件照着填。
- 改公共字段名时加 `[FormerlySerializedAs("旧名")]`，否则预制体上的引用会被清空。

另外，这个工程目前没有版本控制（`git status` 报 not a git repository）。这种规模的结构调整建议先做一次备份，或者初始化 git 提交一版，改坏了能回退。

## 14. 附：ClientNetworkTransform 是什么（网络模块的事，了解即可）

- NGO 自带的 `NetworkTransform` 默认是**服务器权威**：只有主机能改 Transform，客户端自己改了会被主机的同步覆盖掉。
- 权威模式由一个虚方法决定：`protected virtual bool OnIsServerAuthoritative()`（`Runtime/Components/NetworkTransform.cs`）。默认返回 `true`；派生一个子类覆盖成返回 `false`，就变成 owner（客户端）权威——这就是常说的 `ClientNetworkTransform`。
- 这个类不在 NGO 包里，来自官方示例，本体是个十行左右的子类。官方文档 `Documentation~/components/networktransform.md` 里也写了这个做法。
- 它替换的是**预制体上的组件**（`NetworkTransform` → `ClientNetworkTransform`），不是你的脚本，归网络模块做。
- 对你的影响只有一条：本地玩家的移动照常写在本机 `Player_Body` 里；非本地玩家的刚体保持运动学，别去和它抢 Transform。
